# 配置、快捷键和窗口规则

应用读取 JSON 配置。默认位置是 Tauri 的应用配置目录下 `config.json`；Windows 通常为 `%APPDATA%\local.e-desktop.manager\config.json`。可以用环境变量 `E_DESKTOP_CONFIG` 指定完整文件路径。应用不会自动创建或覆盖这个文件。

控制器每 500 ms 检查一次内容变化。保存后自动加载，不需要重启；删除文件恢复默认配置。JSON、字段、规则或快捷键无效时显示错误并保留上次有效配置。系统拒绝注册新快捷键时会尝试回滚；回滚失败也会显示具体错误。启动时配置无效则尝试使用默认快捷键。

配置不保存现有窗口布局，启动后仍然默认暂停；布局另存于状态文件，见[布局保存与恢复](#布局保存与恢复)。窗口规则只在一个窗口 ID 首次被发现时执行，修改规则不会重新排列已发现的窗口。

## 文件结构

```json
{
  "windowRules": [
    { "appName": "notepad", "columnWidth": 800 },
    { "title": "计算器", "floating": true }
  ]
}
```

`shortcuts` 只需写要修改的组合，其余沿用默认快捷键：与默认组合相同的键覆盖默认动作，新组合直接添加，动作 `{ "type": "unbind" }` 删除该默认组合。组合按规范化后比较，`Ctrl+Alt+L` 与 `Control+Alt+KeyL` 视为同一个键。省略 `shortcuts` 或提供空数组都使用全部默认快捷键。

设置 `"defaultShortcuts": false` 时不加载默认快捷键，`shortcuts` 即完整映射；此时 `"shortcuts": []` 或省略 `shortcuts` 会禁用全部全局快捷键。省略 `windowRules` 或提供空数组均不设置窗口规则。

## 自定义快捷键

例如 `Ctrl+Alt+L` 被其他软件占用时，把向右聚焦改到 `Ctrl+Alt+;`，并删除无法注册的原组合：

```json
{
  "shortcuts": [
    { "key": "Control+Alt+L", "action": { "type": "unbind" } },
    { "key": "Control+Alt+Semicolon", "action": { "type": "command", "command": { "type": "focusDirection", "direction": "right" } } }
  ]
}
```

更多动作示例：

```json
{
  "shortcuts": [
    { "key": "Control+Alt+Space", "action": { "type": "commands" } },
    { "key": "Control+Alt+O", "action": { "type": "overview" } },
    { "key": "Control+Alt+Left", "action": { "type": "scroll", "direction": "left" } },
    { "key": "Control+Alt+Right", "action": { "type": "scroll", "direction": "right" } },
    { "key": "Control+Alt+W", "action": { "type": "command", "command": { "type": "setColumnWidth", "width": 800 } } },
    { "key": "Control+Alt+PageDown", "action": { "type": "relativePage", "delta": 1 } },
    { "key": "Control+Alt+Shift+2", "action": { "type": "page", "number": 2, "moveWindow": true } },
    { "key": "Control+Alt+Backspace", "action": { "type": "command", "command": { "type": "disable" } } },
    { "key": "Control+Alt+Q", "action": { "type": "quit" } }
  ]
}
```

支持的动作：

| `action.type` | 参数与行为 |
| --- | --- |
| `command` | `command` 为 [实现契约](implementation-contract.md) 中的命令对象 |
| `overview` / `commands` | 打开概览 / 命令面板 |
| `quit` | 还原后退出 |
| `page` | `number` 为从 1 开始的已有页面编号；可选 `moveWindow` 默认为 false |
| `relativePage` | `delta` 为非零相对偏移；可选 `moveWindow` 默认为 false |
| `scroll` | `direction` 为 `left` 或 `right`：活动显示器向该方向滑动，直到下一个没有完整显示的列完整进入屏幕，并聚焦这一列（沿用当前窗口在堆叠中的行）；该方向已全部可见时改为聚焦相邻列 |
| `unbind` | 删除该默认组合；与 `"defaultShortcuts": false` 一起使用时没有效果 |

页面和滚动动作在执行时读取当前活动显示器，不保存易失效的页面 ID。页面不存在时不执行。`command` 中的 ID 则按提供的值使用；`addPage` 的空 `monitorId` 表示执行时的活动显示器。

默认新增快捷键：

| 快捷键 | 行为 |
| --- | --- |
| `Ctrl+Left/Right`、`Ctrl+Alt+Left/Right` | 向左 / 右滑动一列并聚焦滑入的窗口（`scroll` 动作） |
| `Ctrl+Alt+Shift+Left/Right` | 减少 / 增加列宽 50 物理像素 |
| `Ctrl+Alt+Shift+Up/Down` | 增加 / 减少聚焦窗口高度 50 物理像素 |
| `Ctrl+Alt+Shift+R` | 当前列恢复等高 |

全局快捷键注册后，其他应用收不到这个组合：`Ctrl+Left/Right` 在程序运行期间不再用于文本编辑中的按词移动光标。需要按词移动时，用 `unbind` 删除这两个组合，改用 `Ctrl+Alt+Left/Right`。

宽度和高度命令仅适用于聚焦的平铺、非布局全屏窗口。任意列宽通过 `setColumnWidth` 指定：0 无效，大于视口的值夹到视口宽度。高度调整会重新分配同列其余窗口的空间；窗口顺序、视口变化后保留会话内高度偏好。

## 窗口规则

| 字段 | 含义 |
| --- | --- |
| `appName` | 应用名的字面子串，不区分大小写 |
| `title` | 标题的字面子串，不区分大小写 |
| `floating` | 初始浮动状态；不可缩放窗口始终浮动 |
| `columnWidth` | 初始列宽，正整数物理像素，最大为目标视口宽度 |
| `monitorId` | 目标显示器 ID，需与快照中 ID 完全相同 |
| `pageIndex` | 目标屏已有页面的编号，从 1 开始 |

同时提供 `appName` 和 `title` 时必须都匹配；不提供条件则匹配所有窗口。这两个字段不支持正则表达式或通配符，正则匹配见[下文](#正则窗口规则启动命令和截图)。多条匹配规则逐字段合并，后面的规则覆盖前面规则指定的同一动作字段。每条规则至少有一个动作，条件和显示器 ID 不得为空白。

目标显示器不存在时回退到原生窗口所在显示器；目标页面尚不存在时回退到目标屏当前页面。规则不会创建指定数量的空页。启动时通常只有初始页，因此不能用 `pageIndex` 预创建页面。后台页规则不会主动切页或抢焦点。

窗口名称和 ID 来自原生后端，平台之间可能不同。规则在窗口首次枚举时匹配当时的标题，后续标题变化不触发重新匹配。列宽对浮动窗口无效。

## 外观

```json
{
  "gaps": 0,
  "animationDurationMs": 160,
  "topBar": true,
  "focusBorderColor": "#7fc8ff",
  "windowCorners": "system"
}
```

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `gaps` | `0` | 平铺窗口之间，以及窗口到可用区域边缘的间距，单位是逻辑像素（乘以该显示器的缩放）。默认贴紧，最大 `256`；niri 默认是 `16`。列宽、滚动和高度仍按物理像素计算，用的是扣掉间距之后的内视口 |
| `animationDurationMs` | `160` | 布局动画和概览开合动画的时长，`0` 关闭，最大 `1000`。滚动、聚焦、移动列、调整宽高、打开或关闭窗口时，平铺窗口从当前位置平滑移动和缩放到新位置；切换工作区时旧页向上滑出、新页从下方滑入（反向切换方向相反）。布局动画和概览开合使用同一条曲线：临界阻尼弹簧，在设定时长内准确停在终点；动画中途改变目标时从当前位置和速度继续。各类动画可用 `animations` 分别设置时长（见[动画类型与快捷键提示](#动画类型与快捷键提示)）。布局动画目前只在 Windows 上生效，X11/macOS 直接落到新位置。Windows 上动画由覆盖在显示器上的遮罩用窗口实时缩略图绘制，每块显示器只画自己的窗口（与 niri 相同）；动画期间遮罩下的其他程序窗口暂时看不到，动画开始前约有 30～50 ms 用于准备遮罩和移动真实窗口。拖动窗口松手后各窗口滑到新位置；拖动分界线松手后各窗口平滑过渡到新尺寸 |
| `topBar` | `true` | `false` 时不显示任何顶栏，不为它预留高度，鼠标移到屏幕顶边也不会把它唤出 |
| `focusBorderColor` | `"#7fc8ff"` | 正在管理的窗口的焦点边框颜色，格式 `#rrggbb`。`null` 表示不改系统边框。仅 Windows 11 生效，更旧的系统会忽略 |
| `windowCorners` | `"system"` | 正在管理的窗口的圆角：`system`（不改）、`round`、`roundSmall`、`square`。仅 Windows 11 生效 |

平铺列保持各自的宽度，不因窗口打开、关闭或最小化而自动撑满屏幕。默认切换只滚动到目标列完整可见，边缘允许露出相邻列的一部分；100% 宽列只露出一半时，实际列宽仍是 100%。居中命令允许在首尾留出空白。

用户主动最小化的平铺窗口退出排布和方向切换，还原时回到原工作区、列和上下顺序；原列仍存在时沿用该列当前宽度，整列消失时恢复保存的列宽。用于隐藏离屏窗口或后台工作区的管理器最小化保留布局身份。浮动窗口获得焦点时不滚动平铺区域，也不取消平铺窗口的布局全屏。

Windows 上的间距按窗口的可见边框计算，不把系统那圈不可见的缩放边框算进去。边框颜色和圆角只作用在本程序正在管理的窗口上，暂停并还原时恢复系统默认。布局全屏填满扣掉顶栏后的区域，不再留间距；浮动窗口的位置不变。

## 顶栏滚动

顶栏的横向滚动区支持左右按钮、鼠标滚轮与触控板。按钮每次 160 物理像素；命令面板也提供相同动作。滚轮像素值按显示器缩放比例转换，按行与按页事件分别使用控件行高和视口宽度；对角滚动只取绝对值较大的轴。Ctrl+滚轮 / 捏合不会触发布局滚动。

滚动停在列边缘对齐屏幕左边或右边的位置：按滚动量找最近的对齐位置，如果最近的就是当前位置，就沿滚动方向前进到下一个。

输入按 80 ms 合并，每次只允许一个原生请求在途。忙碌、暂停、目标失效或页面切换时丢弃待处理输入，不延迟追赶。此处没有滚动动画，也不全局拦截其他应用的滚轮。

## 鼠标

### 控制栏自动收起

Windows 上每个显示器的控制栏默认收起，不占用顶部空间。鼠标移到某个显示器的最顶端一行像素时，只显示这个显示器的控制栏，显示时不抢走当前窗口的焦点；鼠标离开控制栏后再次收起。暂停管理时同样有效。

控制栏上的“固定”按钮让该显示器的控制栏常驻，并为它保留顶部空间，平铺窗口随之下移；再次点击（显示为“已固定”）取消固定。固定状态按显示器分别保存，只在本次运行内有效。鼠标钩子安装失败时，以及 X11/macOS 上，控制栏始终固定显示。启用热角时，显示器左上角那一个像素只打开概览，不显示控制栏。`topBar` 为 false 时不显示控制栏，不预留高度，顶边也不会唤出它（见[外观](#外观)）。

### 焦点、拖动和热角

以下功能仅在 Windows 上、且平铺管理启用时生效，暂停后不拦截任何鼠标输入。

```json
{
  "focusFollowsMouse": true,
  "warpMouseToFocus": true,
  "hotCorners": true,
  "dragModifier": "alt"
}
```

| 字段 | 默认值 | 行为 |
| --- | --- | --- |
| `focusFollowsMouse` | `false` | 鼠标进入受管窗口时聚焦该窗口。按住鼠标键、概览或命令面板打开、菜单或对话框等非受管窗口在前台时不切换焦点 |
| `warpMouseToFocus` | `false` | 快捷键、命令面板或概览改变焦点后，若鼠标不在新焦点窗口内，把鼠标移到窗口可见部分的中心 |
| `hotCorners` | `true` | 鼠标进入任一显示器左上角像素时打开该显示器的概览；概览已打开时关闭 |
| `dragModifier` | `"alt"` | `"alt"` 或 `"super"`（Win 键）；`null` 关闭修饰键拖动 |

按住修饰键在受管窗口上左键拖动可移动窗口：浮动窗口跟随鼠标，拖动开始时聚焦该窗口；平铺窗口见下文“拖动窗口”。修饰键加左键的这次点击会被吞掉，应用本身收不到。

Windows 上，游戏、视频等外部应用覆盖整个显示器时，该显示器暂时停止平铺、焦点切换、拖动手势和热角，并隐藏顶栏、概览、命令面板及拖动预览。修饰键点击直接交给应用，其他显示器继续工作。普通最大化、e-desktop 的布局全屏和普通 `100%` 宽列不触发暂停。退出外部全屏后，在下一次刷新时恢复，通常不超过 500 ms。检测依据窗口覆盖整个显示器的范围，包含无边框全屏，不是 Direct3D 独占模式查询。

### 拖动窗口

平铺窗口有两种拖法：按住修饰键左键拖动窗口任意位置，或直接拖动窗口自己的标题栏。鼠标移动几个像素后，鼠标所在的显示器盖上预览层，画出松手后这块屏幕的布局：每个窗口一个框，左上角是标题，中间是占屏幕宽度的百分比（堆叠中的窗口还标高度）；被拖动的窗口用蓝色标出。预览和松手时执行的是同一条布局命令，所见即所得。拖动期间真实窗口不动（拖标题栏时系统移动的窗口被预览层盖住），松手后各窗口滑到新位置。落点按松手时鼠标的位置计算：

- 屏幕顶部中间区域（距屏幕顶边 64 逻辑像素内，排除左右排队边条）：松手后将被拖窗口单独放成整宽、全高的一列；原来在堆叠中的其他窗口留在原列。预览显示 `100%`。普通标题栏拖动和修饰键拖动都支持，独占的是扣掉顶栏和间距后的可用区域。
- 某列中间一半：加入这一列的纵向堆叠，按鼠标落在哪个窗口的上半或下半插到它上方或下方；拖回自己所在的列即在堆叠内换位置。加入后这一页的列不再铺满屏幕宽度时（例如把相邻的另一列整个拖进来），这一列加宽，补上空出的宽度。
- 某列左右各四分之一或空白处：在这里成为新的一列，用来改变列的顺序或把窗口移出堆叠。
- 屏幕左右边缘的窄条（屏幕宽度的 1/24，至少 48 逻辑像素）：窗口成为这一侧的新列，松手后自动滚动到整列可见，并聚焦被拖动的窗口。左侧释放后贴左边，右侧释放后贴右边，其余列保持宽度。拖动预览显示松手后的滚动位置。
- 另一个显示器：规则相同，落到那个显示器的当前页面。形成独立列或左右排队时，按来源与目标的可用宽度换算，保持所占比例；加入已有列的堆叠时，沿用目标列宽。
- 宽度不足一半时：形成独立列或左右排队时，被拖窗口的最小宽度超过屏幕一半，这一列直接占满屏幕宽度。新列旁边（指针所在的列，或空白处左侧的最后一列）是一个 `100%` 宽的列时，两个窗口都能缩到一半就各占 `50%`，有一个不能就都保持 `100%`。
- 高度不足时：加入另一列的纵向堆叠后，只要有一个窗口分到的高度小于它的最小高度，就不堆叠，改为在这一列旁边成为新的一列（指针在该列左半边放左侧，右半边放右侧），各窗口保持整列高度，宽度再按上一条处理。预览显示的就是这个结果。
- 最小宽高在 Windows 上向应用查询（`WM_GETMINMAXINFO`），跨显示器时按两块屏幕的缩放比例换算；应用实际拒绝某个宽度时，窗口留在原位，按测得的最小宽度重新排布。

标题栏拖动开始时按原生命中区域区分移动和边框缩放。已识别的标题栏移动中，Windows 贴靠、最大化还原或跨屏 DPI 变化导致的尺寸改变不作为手动缩放接收；松手采用预览里的落点。真正拖边框时不显示窗口落点预览，松手后约 80 ms 采用新尺寸并重排其他窗口。无法识别的自绘标题栏保留原来的几何判断。

普通标题栏拖动仍经过 Windows 原生移动循环，系统的顶部贴靠栏可能显示；本程序不会全局关闭 Windows Snap，最终按本程序的落点规则放置受管窗口。修饰键拖动由本程序接管，不进入原生标题栏移动循环。

### 拖动分界线

平铺管理启用时，相邻两列的分界线上有一条看不见的拖动条（12 逻辑像素宽，与系统缩放边框的宽度相当，鼠标经过时显示左右调整光标）。屏幕左右边缘如果还藏着一列，边缘上也有一条。普通 `100%` 宽列的左右两侧都有向屏内延伸的拖动条，往中间拖可缩窄，并在接近一半时吸附到 `50%`；应用自身的最小宽度仍会限制结果。同一列里上下堆叠的窗口之间也有一条（上下调整光标）。拖动时整块屏幕盖上同样的预览层，只画拖动后的分割框和百分比，分界线两侧的窗口用蓝色标出；真实窗口在松手后才改尺寸，与其他布局变化一样以动画过渡。

- 拖动两列之间的分界线：一边变宽、一边变窄，其余分界线保持不动，已经贴在屏幕边缘的列仍然贴着。每列至少保留屏幕宽度的 1/10。
- 拖动堆叠窗口之间的分界线：上下两个窗口互相调整高度，每个至少保留屏幕高度的 1/10。
- 吸附：分界线靠近屏幕中线（宽度或高度的 50%）时吸到中线；进入屏幕边缘附近（屏幕宽度或高度的 1/12，至少 64 逻辑像素）时吸到边缘。中线的吸附范围是边缘的三分之一。
- 挤出屏幕：把两列之间的分界线拖到屏幕左边吸住，右侧这列独占整个屏幕宽度，它左边原来在屏幕上的列被挤到屏幕左侧之外（保持原宽度）；拖到右边则左侧这列独占，右边的列被挤到右侧之外。堆叠窗口之间的分界线拖到屏幕顶边（或底边）吸住时，下方（或上方）的窗口占满这一列，分界线扣过的窗口离开堆叠，合成一列排到屏幕外：这一列位于屏幕左半边就挤到左侧，位于右半边就挤到右侧。预览在对应一侧边缘显示被挤出的窗口标签；被挤出的窗口原来有焦点时，焦点交给独占的窗口。
- 拖动贴在屏幕边缘的列边：往屏幕内拖会解除吸附，这一列变窄，藏在边缘外的那一列露出一部分；若吸到中线时屏内这一列已是半屏、屏外邻列仍更宽，且两列的应用最小宽度都允许半屏，则两列都缩到实际 `50%` 并完整显示；拖回边缘则恢复原样。从边缘吸附范围内开始拖的分界线拖回同一边缘时也只是恢复原样，不会挤出窗口。
- 拖动不会把剩余列自动撑满屏幕；居中后的拖动保留未拖动边界的位置。点一下不移动什么也不改。

直接拖窗口自己的边框时本程序不移动任何窗口；松手后约 80 ms 刷新一次，采用新尺寸并重排其他窗口（这条路径没有吸附）。列之间和堆叠窗口之间的边框被上面的拖动条盖住，走的是带预览的路径。

## 列、显示器与焦点历史动作

参照 niri 的同名动作。下表的 `command` 都可以写进 `shortcuts` 的 `command` 动作，也都能在命令面板中搜索；`direction` 取 `left`、`right`、`up`、`down`，只接受左右或上下的命令收到其他方向时报错。

| 命令 `type` | 默认快捷键 | 行为 |
| --- | --- | --- |
| `consumeOrExpelWindow` | `Ctrl+Alt+[ / ]` | 当前窗口所在列有多个窗口时，拆成该侧的新列（沿用原列宽）；单独一列时，并入该侧相邻列的底部 |
| `consumeWindowIntoColumn` | 无 | 右侧相邻列的第一个窗口并入当前列底部 |
| `expelWindowFromColumn` | 无 | 当前窗口从堆叠中拆出，成为右侧新列；单独一列时不变 |
| `moveColumn` | `Ctrl+Alt+Shift+[ / ]` | 当前列与左 / 右相邻列交换位置 |
| `moveColumnToFirst` / `moveColumnToLast` | `Ctrl+Alt+Shift+Home/End` | 当前列移到条带最前 / 最后 |
| `swapWindow` | 无 | 当前窗口与左 / 右相邻列中上次聚焦的窗口互换位置，焦点跟随当前窗口 |
| `focusColumnFirst` / `focusColumnLast` | `Ctrl+Alt+Home/End` | 聚焦活动显示器当前页面的第一列 / 最后一列 |
| `focusWindowOrPage` | 无 | 上 / 下聚焦列内窗口；已在列顶 / 列底时切换到上一个 / 下一个页面 |
| `focusColumnOrMonitor` | 无 | 左 / 右聚焦；已到条带尽头时聚焦该侧的显示器 |
| `focusMonitor` | `Ctrl+Alt+,/.`（左 / 右） | 激活该方向的显示器及其当前页面，聚焦这个页面上次聚焦的窗口；页面为空时它也成为活动显示器 |
| `moveColumnToMonitor` | `Ctrl+Alt+Shift+,/.`（左 / 右） | 当前列移到该方向显示器的当前页面，放在那里上次聚焦的列右侧，焦点跟随；浮动窗口单独移动 |
| `moveWindowToMonitor` | 无 | 当前窗口移到该方向显示器的当前页面，焦点跟随，与“移动当前窗口到页面”相同 |
| `movePageToMonitor` | 无 | 当前页面整体移到该方向的显示器，插在那里当前页面之后，并成为活动页面；空页面不移动 |
| `focusWindowPrevious` | `` Ctrl+Alt+` `` | 回到上一次聚焦的受管窗口，可跨页面和显示器；连按在最近两个窗口间切换。已关闭或被用户最小化的窗口跳过 |
| `focusPagePrevious` | `Ctrl+Alt+P` | 活动显示器回到上一个活动页面；连按在两个页面之间切换。每个显示器分别记录 |

仅命令的动作可以自己绑定，例如：

```json
{
  "shortcuts": [
    { "key": "Control+Alt+U", "action": { "type": "command", "command": { "type": "focusWindowOrPage", "direction": "down" } } },
    { "key": "Control+Alt+I", "action": { "type": "command", "command": { "type": "focusWindowOrPage", "direction": "up" } } },
    { "key": "Control+Alt+Semicolon", "action": { "type": "command", "command": { "type": "focusColumnOrMonitor", "direction": "right" } } }
  ]
}
```

显示器方向按显示器矩形计算：只考虑在该方向上与当前显示器有重叠的显示器，取中心最近的一个；该方向没有显示器时不执行。列与窗口的移动动作只适用于平铺窗口，浮动窗口上执行时报错，与“移动窗口”一致；布局全屏的窗口可以移动。动作结束后焦点窗口滚动到完整可见。焦点和页面历史只保存在本次运行内。

`focusMonitor` 移到空页面时没有窗口可以接收原生焦点，键盘输入仍然交给原来的窗口，直到点击或聚焦其他窗口；在此之前刷新不会把活动显示器拉回原处。目标显示器因外部全屏暂停时，这些动作不执行。

## 布局选项与命名页面

<!-- lane: layout-options -->

以下选项参照 niri 的 `layout` 与 `workspace` 配置，保存后随配置热加载生效；已有列的宽度不会因重载而改变。

```json
{
  "presetColumnWidths": [{ "proportion": 0.33333 }, { "proportion": 0.5 }, { "proportion": 0.66667 }, { "fixed": 1280 }],
  "defaultColumnWidth": { "proportion": 0.5 },
  "presetWindowHeights": [{ "proportion": 0.33333 }, { "proportion": 0.5 }, { "proportion": 0.66667 }],
  "centerFocusedColumn": "onOverflow",
  "alwaysCenterSingleColumn": true,
  "struts": { "left": 64, "right": 64, "top": 0, "bottom": 0 },
  "workspaces": [{ "name": "chat", "monitor": "\\\\.\\DISPLAY2" }, { "name": "web" }],
  "windowRules": [{ "appName": "slack", "pageName": "chat" }],
  "shortcuts": [
    { "key": "Control+Alt+Shift+C", "action": { "type": "pageByName", "name": "chat" } },
    { "key": "Control+Alt+Shift+W", "action": { "type": "pageByName", "name": "web", "moveWindow": true } }
  ]
}
```

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `presetColumnWidths` | 1/3、1/2、2/3 | `cycleWidth`（`Ctrl+Alt+R`）按数组顺序循环的列宽；`cycleWidthBack`（仅命令面板）反向循环。当前宽度等于某个预设时切到下一个，否则切到沿循环方向第一个更宽（反向时更窄）的预设 |
| `defaultColumnWidth` | `{ "proportion": 0.5 }` | 新列的宽度；窗口规则的 `columnWidth` 优先 |
| `presetWindowHeights` | 1/3、1/2、2/3 | `cycleWindowHeight`（`Ctrl+Alt+Shift+E`）把聚焦窗口在列内的高度循环设为这些值，同列其余窗口按原有比例分配剩余高度；列中只有一个窗口时不变 |
| `centerFocusedColumn` | `"never"` | `never`：只滚动到聚焦列完整可见；`always`：聚焦列总是居中；`onOverflow`：聚焦列与焦点来源一侧的相邻列放不进同一屏时才居中 |
| `alwaysCenterSingleColumn` | `false` | 页面只有一列时让它居中 |
| `struts` | 全为 `0` | 从布局区域左、右、上、下各扣掉的逻辑像素（乘以该显示器的缩放），与固定顶栏占位叠加，再在其内留出 `gaps` |
| `workspaces` | `[]` | 命名页面，见下文 |

预设和 `defaultColumnWidth` 的每一项只能是 `{ "proportion": 比例 }` 或 `{ "fixed": 逻辑像素 }` 之一：比例须大于 0 且不超过 1，列宽相对扣掉间距后的视口宽度，窗口高度相对列高；`fixed` 是窗口本身的宽或高（正整数逻辑像素，乘以缩放后再加上两侧间距），超过视口时夹到视口大小。预设数组不能为空。比例、像素或字段名不合法时整个配置报错，保留上次有效配置。

居中设置在焦点变化和“确保焦点列可见”的滚动时生效（切换焦点、移动窗口、调整宽度等）；比视口还宽的列靠左对齐，不居中。`Ctrl+Alt+C` 的手动居中不受这些设置影响。

`maximizeColumn`（`Ctrl+Alt+Shift+M`）把当前列切换为视口全宽，窗口仍在平铺中、保留间距和顶栏，不同于 `Ctrl+Alt+F` 的布局全屏；再次执行恢复切换前的宽度。若列已是全宽且没有记录的原宽度（例如手动设成全宽），恢复为 `defaultColumnWidth`。

### 命名页面

`workspaces` 中每项为 `{ "name": "名称", "monitor": "显示器名称或 ID" }`，`monitor` 可省略。`monitor` 须与显示器的完整名称（不区分大小写）或 ID 完全一致：Windows 上名称形如 `\\.\DISPLAY2`，写进 JSON 时每个反斜杠都要转义，即 `"\\\\.\\DISPLAY2"`；只写 `DISPLAY2` 匹配不到。运行 `e-desktop-msg pages` 可以看到每块显示器的 `显示器 名称 (ID)`，快照中对应 `monitors[].monitor` 的 `name` 和 `id`，复制其中之一即可。名称不能为空白，不区分大小写且不能重复。启动时（以及修改了 `workspaces` 的配置重载后）为尚不存在的名称创建页面，按声明顺序排在该显示器的未命名页面之前；`monitor` 未写或找不到时放在主显示器上。启动时已有的窗口仍留在原来的未命名页面。

带名称的页面即使为空也不会被自动回收；顶栏页面按钮显示名称而不是编号，概览、命令面板和顶栏位置也显示名称。命令：

| 命令 | 行为 |
| --- | --- |
| `{ "type": "setPageName", "name": "..." }` | 给活动显示器的当前页面命名；其他页面已用这个名称时，那个页面的名称被取消 |
| `{ "type": "unsetPageName" }` | 取消当前页面的名称；之后若为空且不是当前页面，按普通页面回收 |

命令面板中输入 `命名 名称` 或 `name 名称` 会出现“命名当前页面为 名称”的条目，另有“取消页面命名”。暂停管理时这两个命令与其他布局命令一样不执行。

快捷键动作 `{ "type": "pageByName", "name": "...", "moveWindow": false }` 在执行时按名称查找页面：`moveWindow` 为 false 时切换到该页面（可在另一块显示器上），为 true 时把聚焦窗口移到该页面并跟随。名称不存在时不执行。

窗口规则可增加 `pageName`：新窗口打开到该命名页面，优先于 `monitorId` 与 `pageIndex`；名称不存在时按 `monitorId` / `pageIndex` 的规则回退。与 `pageIndex` 一样，打开到后台页面不会切页或抢焦点。

默认新增快捷键：

| 快捷键 | 行为 |
| --- | --- |
| `Ctrl+Alt+Shift+M` | 切换当前列最大化（视口全宽 / 恢复原宽度） |
| `Ctrl+Alt+Shift+E` | 循环聚焦窗口在列内的预设高度 |

## 标签列

参照 niri 的 tabbed column display：列可以在“纵向堆叠”和“标签”两种显示方式之间切换。标签列有两个及以上窗口时只显示其中一个（当前标签），它占满整列高度，只在顶部留出 12 逻辑像素给标签指示器；其他标签被本程序最小化，用的是和移出屏幕的列、后台页面相同的可还原方式，暂停并还原或退出时与其他窗口一样恢复原状。列里只剩一个窗口时与普通列完全相同，不留指示器空间。

```json
{
  "defaultColumnDisplay": "tabbed"
}
```

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `defaultColumnDisplay` | `"normal"` | 新建列的显示方式：`normal`（纵向堆叠）或 `tabbed`（标签）。只影响之后新建的列（新窗口、拆出或拖成独立的一列、移到其他页面），已有列不变；窗口并入已有列时沿用那一列的显示方式 |

切换命令为 `{ "type": "toggleColumnTabbedDisplay" }`，作用于聚焦窗口所在的列，默认快捷键 `Ctrl+Alt+W`；命令面板中为“切换标签列 Tabbed column”。浮动窗口没有列，不能切换。

- 上下聚焦（`Ctrl+Alt+J/K`）在标签之间切换；左右聚焦进入标签列时回到这一列的当前标签。加 `Shift` 的上下移动调整标签顺序。
- 窗口用快捷键左右并入标签列时排在最后一个标签，拖放到标签列中间一半时插在当前标签后面，两种情况都成为当前标签。拖到列的左右四分之一仍然形成新列。
- 标签列内没有上下分界线，调整高度和恢复等高对它不起作用。关闭聚焦中的当前标签后，焦点和显示交给同列的下一个（没有则上一个）标签。从任务栏等处激活一个被隐藏的标签，它会成为当前标签。
- 拖动窗口的预览把标签列画成一个窗口框。

Windows 上，标签指示器是一条画在保留空间里的分段条：每段一个标签，当前标签为浅蓝色，点击某一段切换到那个标签。指示器是不置顶、不会激活的小窗口，只占保留出来的那一条，不盖住窗口内容，也不抢焦点；布局动画期间它被动画遮罩盖住，动画也不会画出被隐藏的标签。X11/macOS 上没有指示器，顶部仍留出同样的空间。

概览中，标签列只显示当前标签的窗口卡片，上方一排按钮列出所有标签的标题，当前标签高亮；点击按钮切换标签，概览保持打开。拖动当前标签的卡片和拖入标签列的规则与桌面上相同。

## 动画类型与快捷键提示

### 按类型设置动画时长

```json
{
  "animationDurationMs": 160,
  "animations": {
    "workspaceSwitch": 250,
    "viewMovement": null,
    "windowResize": 0,
    "overviewOpenClose": 200
  }
}
```

`animations` 中每一项是毫秒数（`0` 到 `1000`），`0` 只关闭这一类动画；省略或写 `null` 时沿用 `animationDurationMs`。因此只写 `animationDurationMs` 的旧配置行为不变；`animationDurationMs: 0` 时仍可以单独打开某一类。

| 字段 | 覆盖的动画 |
| --- | --- |
| `workspaceSwitch` | 任一显示器的当前页面发生变化：切换或新增页面、回到上一个页面、把页面移到其他显示器、把窗口移到其他页面并跟随、聚焦其他页面上的窗口 |
| `viewMovement` | 横向视口移动：滚动、滑动一列、居中、方向聚焦和点选聚焦、聚焦首列 / 末列、聚焦其他显示器或上一个窗口、触控板横向滑动及松手吸附 |
| `windowMovement` | 窗口换位：移动窗口或列（含移到最前 / 最后、移到其他显示器）、并入或移出列、与相邻列交换窗口、拖动窗口松手、移到其他页面（不跟随）、切换浮动、布局全屏或标签列 |
| `windowResize` | 尺寸变化：循环列宽（含反向）、循环窗口高度、列最大化、设置或增减列宽和高度、恢复等高、拖动分界线松手 |
| `windowOpenClose` | 窗口出现或消失后的重排（含启用平铺、关闭窗口、刷新）；这类重排发生时如果已有动画在进行，沿用那段动画的时长 |
| `overviewOpenClose` | 概览打开和关闭时缩略图的缩放 |

每次布局变化只使用一个时长。页面发生变化时总是按 `workspaceSwitch`；没有列在表中的命令（暂停、页面命名、截图等本身不移动窗口的命令）使用 `animationDurationMs`。布局动画仍然只在 Windows 上生效。

### 快捷键提示

`Ctrl+Alt+/`（动作 `{ "type": "hotkeyOverlay" }`）打开或关闭快捷键提示窗口，列出当前实际生效的全局快捷键：已经合并了配置中的覆盖和新增组合，`unbind` 删除的组合和被其他软件占用、注册失败的组合不显示。条目按聚焦、移动窗口、视口、尺寸、窗口、工作区、界面、应用分组，同一动作的多个组合合并为一行；无法识别的动作显示动作类型和参数。

提示窗口显示在活动显示器中央，打开时获得键盘焦点，但不遮挡屏幕其他部分，鼠标仍可直接操作其他窗口。按 `Esc`、点击提示窗口或再按一次 `Ctrl+Alt+/` 关闭，焦点回到原来的窗口；点击其他窗口时提示窗口也会关闭，焦点留在被点击的窗口。

```json
{ "hotkeyOverlay": { "skipAtStartup": true } }
```

与 niri 一样，本次运行中第一次启用平铺时自动显示一次提示窗口；`skipAtStartup` 为 `true` 时不自动显示，默认 `false`。

### 概览缩放

概览打开时，按住 `Ctrl` 滚动鼠标滚轮或在触控板上捏合，可以连续放大或缩小工作区预览：向上滚动或张开手指放大，滚轮每格约 1.5 倍。比例相对于自动适配的大小，范围 0.5～2 倍，在本次运行中保留，下次打开概览沿用。拖动窗口、拖动列边缘调宽和落点计算都按当前比例换算回物理像素；拖动进行中忽略缩放。

## 滚轮与触控板手势

以下功能仅在 Windows 上、且平铺管理启用时生效，暂停后滚轮和触控板完全交给系统与应用。X11/macOS 接受这两个字段，但没有效果。

```json
{
  "wheelModifier": "super",
  "touchpadGestureFingers": 3
}
```

| 字段 | 默认值 | 行为 |
| --- | --- | --- |
| `wheelModifier` | `"super"` | 按住修饰键滚动滚轮切换页面或聚焦列：`"super"`（Win 键）、`"alt"`、`"controlAlt"`（Ctrl+Alt）；`null` 关闭 |
| `touchpadGestureFingers` | `null` | 精确式触控板多指滑动的手指数，`3` 或 `4`；`null` 关闭 |

### 修饰键 + 滚轮

- 修饰键 + 纵向滚轮：鼠标所在显示器向上滚切到上一页，向下滚切到下一页（最后是末尾的空页），到头不循环。
- 修饰键 + Shift + 纵向滚轮，或修饰键 + 横向滚轮（倾斜滚轮、触控板双指横向滚动）：向左 / 右聚焦一列，与 `focusDirection` 相同（对应 niri 的 focus-column-left/right）。Shift 加向下滚为向右。鼠标所在显示器不是焦点所在的显示器时，先聚焦这块显示器当前页面上次聚焦的窗口，再移动一列；该页面没有窗口时不执行。
- 修饰键须完全一致：`"super"` 时同时按着 Ctrl 或 Alt 不触发，`"controlAlt"` 时按着 Win 不触发；Shift 只改变方向。不一致时滚轮照常交给应用。
- 被处理的滚轮事件会被吞掉，应用收不到。普通滚轮每格触发一次，两次触发之间至少间隔 150 ms（同 niri 默认的 `cooldown-ms=150`），冷却期内的格子直接丢弃。高精度滚轮和触控板双指滚动的细分事件累计满一格（120）才触发；反向滚动或停顿 500 ms 后重新累计。
- 只按 Win 或 Alt 滚动后松开，本会弹出开始菜单或激活应用的菜单栏。处理滚轮时会注入一次没有作用的按键（虚拟键 `0xE8`，与修饰键拖动相同），松开修饰键不再弹出。
- 概览或命令面板打开、按住鼠标键、鼠标所在显示器因外部全屏应用暂停时，滚轮不被拦截，直接交给应用。菜单、对话框等非受管窗口在前台或正在修饰键拖动窗口时，滚轮被吞掉但不执行动作（与焦点跟随鼠标的抑制规则相同）。

### 触控板手势

需要精确式触控板（Windows 设置里有“触控板”页面的设备）。程序通过 Raw Input 只读取触点，拦截不了系统手势：使用前须在 Windows“设置 > 蓝牙和其他设备 > 触控板”中，把与 `touchpadGestureFingers` 相同指数的手势（“三指手势”或“四指手势”）的“轻扫”设为“无”，否则切换应用、显示桌面、任务视图等系统手势会同时触发。

- 横向滑动：视图实时跟随手指，内容随手指移动（手指向左滑，右边的列进入屏幕），滑过整块触控板宽度约移动 1.5 个屏幕宽。松手时按手指速度加上惯性距离（niri 的触控板减速曲线），停在离该位置最近的列边缘（某列左边或右边与屏幕对齐），并聚焦滑动方向上最远的一个完整显示的列。
- 纵向滑动：松手时手指移动超过触控板宽度的 12% 才切换页面：手指向上滑进入下一页，向下滑回到上一页（与 niri 相同，内容跟随手指）。
- 手指移动超过触控板宽度的 4% 后才确定是横向还是纵向。滑动中手指数变化即视为松手；触点多于设定指数时，在手指全部离开前不再识别手势。
- 手势作用于开始时鼠标所在的显示器。概览或命令面板打开、正在修饰键拖动、非受管窗口在前台或该显示器因外部全屏暂停时，手势不开始。
- 横向拖动时真实窗口逐帧移动，不使用动画遮罩；松手后的吸附有布局动画。命令面板的“视图对齐到最近的列”执行同样的吸附（不带惯性）。

这两步对应 IPC 命令 `dragViewport`（`monitorId`、`delta`：视图移动的物理像素，不吸附、不改焦点）和 `snapViewport`（`monitorId`、`delta`：在当前位置上加这段距离后吸附到最近的列边缘并聚焦）。

## 布局保存与恢复

<!-- lane: persistence-ipc -->

平铺启用期间，布局变化后约 1 秒（没有新的变化时）写入状态文件；暂停平铺和退出时立即写入尚未保存的变化。暂停期间不保存，因此暂停后关闭的窗口不会从已保存的布局中删除。状态文件位于配置文件同一目录下的 `layout-state.json`，Windows 通常为 `%APPDATA%\local.e-desktop.manager\layout-state.json`；用 `E_DESKTOP_CONFIG` 指定配置文件时随之放在该文件所在目录。

| 字段 | 默认值 | 行为 |
| --- | --- | --- |
| `restoreLayout` | `true` | 本次运行第一次启动平铺时，若存在状态文件，按其中的布局重建；`false` 时忽略状态文件（仍然保存） |

状态文件保存每个显示器的全部页面（名称、滚动位置等所有字段）、列（列宽等所有字段）、列内顺序、浮动窗口及其矩形、活动页面、活动显示器、焦点窗口和堆叠高度比例。恢复时：

- 显示器先按设备 ID、再按名称（Windows 为 `\\.\DISPLAY1` 这类设备名）匹配，剩下的按顺序对应。没有对应的已保存显示器不恢复，当前显示器上没有对应的页面保持原样。
- 窗口 ID 只在一次运行内有效，所以按以下顺序逐级匹配，每个已保存条目最多对应一个窗口，每个窗口也只用一次：同一 ID 且同一进程；进程仍在运行（进程 ID 与可执行文件相同）且标题相同；可执行文件与标题相同；进程仍在运行；可执行文件相同。Windows 上可执行文件即 `appName`（如 `Code.exe`），X11 上为 WM_CLASS；后端不提供窗口类，因此不参与匹配。
- 匹配到的窗口回到保存的页面、列与行，浮动窗口回到保存的矩形（显示器位置不同时按可用区域平移并限制在屏幕内）。已不能调整大小的窗口改为浮动。
- 未匹配的窗口按普通新窗口处理，窗口规则照常生效。

只恢复一次：之后的暂停与启动沿用当前会话的布局。状态文件无法解析或版本不符时忽略该文件并在错误区显示原因，布局按普通方式建立；之后的保存会覆盖它。

## 正则窗口规则、启动命令和截图

### 正则匹配

窗口规则除了上文的 `appName` / `title` 字面子串，还可以写 niri 式的 `matches` 和 `excludes`。两者都是对象数组，每个对象可写 `appName`、`title`，值为正则表达式：

```json
{
  "windowRules": [
    { "matches": [{ "appName": "(?i)^firefox\\.exe$", "title": "(?i)picture-in-picture" }], "floating": true },
    { "matches": [{ "appName": "(?i)^Code\\.exe$" }, { "appName": "(?i)^WindowsTerminal\\.exe$" }], "excludes": [{ "title": "设置" }], "openMaximized": true },
    { "excludes": [{ "appName": "(?i)^explorer\\.exe$" }], "maxWidth": 1600 }
  ]
}
```

- 同一对象里的条件必须都匹配；`matches` 中任一对象匹配、且 `excludes` 中没有对象匹配时规则才生效。省略或空的 `matches` 表示不额外限制，只写 `excludes` 即匹配其余所有窗口。
- 旧的 `appName` / `title` 子串条件保留，与 `matches` / `excludes` 同时写时也必须满足。
- 正则为非锚定搜索并区分大小写，与 niri 相同；需要整串匹配请写 `^…$`，不区分大小写请加 `(?i)`。语法见 Rust [regex](https://docs.rs/regex/latest/regex/#syntax) 库。
- Windows 上 `appName` 是带扩展名的可执行文件名（如 `Code.exe`），整串匹配时要把 `.exe` 写进去；点号在正则里要写成 `\.`，放进 JSON 字符串再转义一次，即 `"^Code\\.exe$"`。X11 上 `appName` 是 WM_CLASS，没有扩展名；同一份配置要兼顾两边可写 `"(?i)^code(\\.exe)?$"`。可执行文件名的大小写因程序而异，建议加 `(?i)`。
- 正则在加载配置时编译，写错的正则作为配置错误显示，并保留上次有效配置。`matches` / `excludes` 中的对象至少要有一个字段。

新增的动作字段（同样只在窗口首次被发现时执行，多条规则按顺序合并，后面的覆盖前面的）：

| 字段 | 含义 |
| --- | --- |
| `openMaximized` | `true` 时新窗口的列占满视口宽度，优先于 `columnWidth` |
| `openFullscreen` | `true` 时新窗口以布局全屏打开（同 `Ctrl+Alt+F`）；不可缩放的窗口不受影响 |
| `openFocused` | `false` 时新窗口不抢焦点：若它打开时或打开后不久（之后约 10 次刷新，约 5 秒内）首次拿到系统焦点（包括已因在屏幕外被最小化时），焦点交还给原来的窗口，视图不变；之后用户自己点它仍会正常聚焦。`true` 时即使应用没有自己激活，也会聚焦新窗口（必要时切到它所在的页面）。只在平铺管理启用时生效 |
| `minWidth` / `maxWidth` | 窗口宽度上下限，逻辑像素（乘以所在显示器的缩放）。平铺列的宽度保持在限制内，列中有多个窗口时取最严的限制；手动调宽、循环列宽和拖动分界线的结果也会被夹回。应用自身的最小宽度和视口宽度仍然优先 |
| `minHeight` / `maxHeight` | 窗口高度上下限，逻辑像素。同一列的堆叠窗口先满足这些限制，剩余高度按原比例分给其他窗口；所有窗口都到达上限时列底部留空，最小高度放不下时按比例缩小 |

尺寸限制按窗口保存，之后修改规则不会改变已发现窗口的限制；浮动窗口和布局全屏不受尺寸限制影响。上下限都必须大于 0，同一方向的最小值不能大于最大值。

不提供 niri 的 `opacity`：Windows 上设置窗口透明度需要把它变成分层窗口（`WS_EX_LAYERED`），而分层窗口无法使用本程序依赖的窗口区域裁剪（见 README），屏幕边缘露出一部分的平铺窗口会因此无法放置。

### 启动命令

```json
{
  "spawnAtStartup": [["C:\\Program Files\\Everything\\Everything.exe", "-startup"]],
  "shortcuts": [
    { "key": "Control+Alt+T", "action": { "type": "spawn", "command": ["wt.exe", "-d", "C:\\"] } },
    { "key": "Control+Alt+Shift+T", "action": { "type": "spawnSh", "command": "start \"\" notepad && start calc" } }
  ]
}
```

| 项 | 行为 |
| --- | --- |
| `spawn` 动作 | `command` 为 `[程序, 参数...]`，直接启动，不经过 shell，参数中的 `%VAR%` 不会展开。程序名按系统 `PATH` 查找。控制台程序会得到它自己的控制台窗口 |
| `spawnSh` 动作 | `command` 为一整行命令。Windows 用 `cmd.exe /S /C` 执行且不显示 cmd 的控制台窗口，Linux/macOS 用 `sh -c`。需要可见控制台的程序请用 `start` 或改用 `spawn` |
| `spawnAtStartup` | 与 `spawn` 相同格式的数组，程序启动时按顺序各执行一次；热加载配置不会再次执行 |

子进程与本程序分离运行，标准输入输出被丢弃，本程序退出时不会结束它们。启动失败（例如找不到程序）显示在错误信息里。这些动作没有默认快捷键。

### 截图

| 快捷键 | 动作 `type` | 行为 |
| --- | --- | --- |
| `Ctrl+Alt+S` | `screenshot` | 冻结当前所有显示器的画面，拖动鼠标框选区域（可以跨显示器）。`Enter` 或空格确认，没有框选时截取鼠标所在的显示器；`Esc` 或右键取消。重新拖动即重新框选 |
| `Ctrl+Alt+Shift+S` | `screenshotScreen` | 截取当前活动显示器 |
| `Ctrl+Alt+Shift+X` | `screenshotWindow` | 截取当前前台窗口；命令面板或概览在最前面时截取布局中的焦点窗口 |

命令面板中也有对应的三条命令，执行时先收起面板再截图；用快捷键截图时，打开着的概览、命令面板和快捷键提示同样先收起；也可以用 `{ "type": "command", "command": { "type": "screenshot" } }` 等形式绑定。截图在暂停管理时同样可用，外部全屏程序暂停该显示器时也不会被拦截。

```json
{ "screenshotPath": "D:\\截图\\%Y%m%d-%H%M%S.png" }
```

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `screenshotPath` | `"%USERPROFILE%\\Pictures\\Screenshots\\Screenshot from %Y-%m-%d %H-%M-%S.png"` | PNG 保存路径。先展开 `%NAME%` 形式的环境变量（未定义的保持原样），再替换 `%Y`、`%m`、`%d`、`%H`、`%M`、`%S`（本地时间）和 `%%`。目录不存在时自动创建，同名文件会被覆盖。`null` 表示不保存文件，只复制到剪贴板 |

每次截图都会把图片以位图（CF_DIB）复制到剪贴板。保存或复制失败时显示错误；一次截图未结束前再次触发会提示上一次尚未完成。框选期间不响应热角、焦点跟随鼠标和修饰键拖动。

截图只支持 Windows，X11/macOS 返回“未实现”错误。实现方式：显示器和区域截图用 GDI 从屏幕复制已合成的画面（包括分层窗口，不包括鼠标指针）；窗口截图在窗口完整显示在屏幕上且没有被本程序裁剪时同样复制屏幕上这块区域，因此盖在它上面的置顶窗口也会被截进去；窗口被裁剪或部分在屏幕外时改用 `PrintWindow`（`PW_RENDERFULLCONTENT`）让窗口自己绘制，个别应用可能返回黑色画面。最小化的窗口无法截图。PNG 由 Windows Imaging Component 编码。
