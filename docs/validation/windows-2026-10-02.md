# Windows 开发与验证记录 — 2026-10-02

## 范围与分工

基线为 `ba3fc1d`。本轮由 1 个只读 scout 核对接口，随后 9 个 worker 在独立 worktree 中并发开发。worker 只负责实现和针对性测试；主 assistant 负责共享接口决策、逐项代码 review、合并和本机验收。没有委派 reviewer，也没有让 worker 操作桌面。

已合入的功能：

- 新平铺窗口插在目标页当前平铺列之后；横向切换记住各列上次聚焦的窗口。记忆只在当前会话内保存。聚焦浮动窗口、没有可用平铺列时，新窗口仍追加。
- 滚动 IPC 执行期间累计输入，包括反向输入；用 `busyCommand` 区分自己的滚动与其他忙碌操作，避免调用端提前丢弃输入。
- 概览支持同页插列／堆叠和后台页原子拖放；拖动、调宽时保持预览槽位，退出统一经过缩放关闭流程。
- 预览 effect 重建会等待同一 session 的旧清理完成，修复 React StrictMode 下旧清理清空新预览的竞态。
- 动画重定向保留已显示位置和速度；使用带终点修正的临界阻尼弹簧，保持原 `animation_duration_ms` 契约。帧截止时间按起点对齐，跳过错过的帧，避免提前唤醒时重复绘制。
- DWM 遮罩先准备缩略图再显示，保留首次 `DwmFlush`，完善失败和取消清理。动画视口暂时拦截鼠标；app 同时抑制按最终 HWND 位置触发的焦点跟随和新拖动，已有释放／取消事件继续处理。
- Windows 后台预览使用最近完成的隐藏前快照，恢复后切回实时 DWM 预览。
- 两个独立实验目录：公开 WGC 纹理捕获；私有共享 Visual 的只读能力探测。

主 assistant 另外修正了 Rust 严格配置镜像、原生拖放构造、TypeScript 共享类型及 Windows API feature 的集成，并扩展了已有 PID 限定原生 smoke。

## 共享契约

`dropWindow { windowId, x, y, pageId?, viewportX? }` 保留旧桌面调用。提供 `pageId` 时原子定位目标页；`viewportX` 只能与它一起使用，覆盖本次命中几何并禁用桌面专用边缘／顶部热区，不提前修改存储的滚动位置。后台页拖放不会激活该页，必要时修复源页焦点。

概览按目标显示器物理视口、缩放比例、客户端边框和实际 `scrollLeft` 映射坐标。负原点、负 viewportX leading、独立概览滚动及无效输入均有测试。

## 缓存与动画的已知限制

快照只为本 backend 已明确接管、可见且没有部分裁剪的窗口预热；读取全桌面元数据不会自动捕获未接管窗口。全局最多每 500 ms 派一次捕获，同一源最多每 5 秒一次；最多一个在途请求，没有积压队列。隐藏时只收取已经完成的结果并取消过期捕获，不等待 PrintWindow。

缓存像素上限 32 MiB；全分辨率捕获 DIB 上限 32 MiB；缩小图最长边 1024、单图最多 4 MiB；静态预览表面另有 32 MiB 合计／4 MiB 单层上限。整个子系统峰值并非只有 32 MiB，另有临时 DIB、像素副本和 native/GPU 开销。

首次立即隐藏、超大窗口、返回黑帧或不支持 PrintWindow 的窗口仍可能没有快照。最小化期间显示的是旧画面。PrintWindow 永久阻塞时，唯一 worker 及其有界资源保留到调用返回或进程退出；控制线程不会等待它，也不会再生成更多捕获线程。

动画仍使用名义 16 ms 调度，首次 DwmFlush 仍是同步调用；没有宣称逐显示器刷新率同步。恢复最小化源到缩略图可用之间仍可能短暂露出最终位置。动画鼠标策略是临时阻止错误命中，不是将输入精确映射到动画中的第三方表面。

本轮没有证明已达到 niri 的合成器级视觉和交互一致性。高刷新率、长时间资源稳定性、真实应用组合以及主观动画效果仍需专项验证。上面的临时日志路径受本机清理策略影响；本文件保留了必要结果和限制。
