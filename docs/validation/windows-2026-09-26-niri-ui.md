# Windows UI 与 niri 对齐检查

日期：2026-09-26。参考 niri 官方 [Overview](https://niri-wm.github.io/niri/Overview.html)、[默认配置](https://github.com/niri-wm/niri/blob/main/resources/default-config.kdl) 和概览演示视频。niri 的壁纸、状态栏及应用主题并非统一固定外观，此次对齐默认布局和概览结构。

## 修改

- 概览从包含常驻表单的全宽卡片列表改为当前显示器的纵向工作区；显示器按钮切换查看目标。
- 工作区和列使用相同的半尺寸比例，跨屏查看时根据可用宽度缩小；按 viewportX 初始化横向位置，包括负偏移居中和末尾留白。
- DWM 缩略图使用窗口预览的主要面积。标题与编辑控件位于预览矩形外，不使用会令原生预览失效的 CSS transform 或祖先透明度。
- 列宽输入和跨屏移动下拉框收进原生 details；拖动窗口和列边缘继续调用原有命令。
- 概览背景 #262626、焦点 #7fc8ff；移除独立原生侧栏，工作区编号放进 36 CSS 像素顶栏。更新原生预留几何、窗口配置和 capability 范围。
- 概览窗口间距取 niri gaps 16、焦点环取 4 逻辑像素，随概览缩放；焦点环画在窗口外侧。工作区阴影使用 niri workspace-shadow 默认值（按 1080 高度归一化），工作区垂直间隔为缩放后高度的 10%。隐藏可见标题和每页窗口计数。
- 列宽循环改为 niri 默认的 1/3、1/2、2/3，完整宽度由布局全屏提供。

## Windows 实机检查

正常退出原应用后启动本轮 debug 程序。GUI 全程保持暂停，未对用户窗口启用平铺。通过临时 WebView2 调试端口读取真实 DOM 和 IPC 快照；检查结束后正常退出测试进程，重新启动不带调试端口的应用。

- 三屏快照确认视口宽度等于 workArea.width，没有左侧预留。顶部偏移分别为 36、54、36 物理像素，对应 100%、150%、100% 缩放。
- 4K 主屏概览：Webview 为 2560 × 1392 CSS 像素，工作区为 1280 × 678；可见 DWM 槽位为 628 × 605，两个源窗口状态 ready。已查看实际主屏截图，预览与标题没有重叠。
- 1080 像素宽的竖屏：本屏工作区为 540 × 918；切换查看 4K 屏后缩小至 1000 × 529.6875。文档无横向溢出。
- 编辑控件初始折叠，点击后展开。实机调用 React 键盘事件验证 Tab 和 Shift+Tab 可以正确循环，排除折叠表单；测试中仅临时解除 DOM 控件的 disabled 属性，未发送管理命令。
- 本机既有 Ctrl+Alt+L/R 注册冲突仍会显示错误，未修改用户快捷键配置。Orca 对次屏的截图坐标存在既有偏差，混合 DPI 结论依据实际 Webview DOM 和原生快照，不以黑色次屏截图作为像素验证。

## 尚有差异

日常保留顶栏；窗口间距、原生焦点边框/圆角、壁纸和合成器级概览缩放动画没有复刻。浮动窗口仍单独排列。当前概览是 Webview 与 DWM 预览组合，不是 niri 合成器的完整桌面缩放。此次没有重新执行真实窗口拖动/调宽、触控板手势或 Linux/macOS 实机检查；对应命令与取消行为由现有前端测试覆盖。
