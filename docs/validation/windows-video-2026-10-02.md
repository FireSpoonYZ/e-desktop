# Windows 录像实机测试 — 2026-10-02

## 结果

本轮发现了可见的动画交接异常，以及一次同页堆叠拖放后的交互／命令无响应。完整交互验收未通过。

被测版本：`d0cda0de8c70b25f48b3844b48cbd20dadd81476`；程序为 `target/debug/e-desktop.exe`。本轮没有修改产品代码。

## 环境与输入路径

- Windows 26200；主屏 3840 × 2160，150% 缩放；另有两个显示器。本轮只录制主屏。
- 新建独立 Windows 虚拟桌面，使用真实 Tauri/WebView2 应用和 5 个自建 WinForms 测试窗口。启动管理前核验，窗口枚举中只有本轮 fixture PID 43620。
- fixture 每个窗口显示独立名称及递增计数，用来区分实时与静态画面。
- 使用独立 `E_DESKTOP_CONFIG`，关闭默认快捷键、焦点跟随、热角和 modifier drag，列宽设为 1500 物理像素。用户原配置未改。
- 点击、滚轮、拖放和 Escape 经 Win32 `SendInput` 输入到真实窗口；窗口坐标来自实际 WebView DOM 和 DPI。它们属于系统合成输入，不是人工硬件鼠标测试。
- 状态读取、预热时的窗口聚焦和快速重定向场景使用 WebView2 CDP 与真实 Tauri IPC；没有伪造后端状态。
- 正式录像使用 FFmpeg gdigrab 采集 4K 桌面，缩小为 1080p，经 NVENC 编码。Desktop Duplication 最初的短探针成功，但后续初始化等待未产出帧，正式录像改用 gdigrab；这项录制工具问题不计为产品缺陷。
- 正式录像共 1234 帧，平均约 25.48 帧／秒；帧间隔中位数 33.33 ms，最大 100 ms。不能据此证明高刷新率流畅度，也不能排除采样间隙内的单帧异常。
- `events.jsonl` 的 `videoMs` 是依据编码进度估算的时间，有管线延迟；下列区间供定位，精确画面时间以录像 PTS 为准。

### 问题 1：滚动动画期间深色背景闪现，恢复窗口短暂露出旧尺寸内容

对 3.2–6.6 秒区间的实际录制帧进行连续抽帧检查，发现未被窗口覆盖的区域在壁纸和大块深色底之间切换。该变化在向右、反向及快速重定向中多次出现。

在 **3.633333 秒**，窗口 C 的标题栏已横向展开，但黄色内容仍只有一小块旧尺寸区域；下一录制帧 **3.666667 秒**内容扩大。这是可见的交接不一致，不是仅依据几何断言推测。未测得该状态的精确持续时间。

证据：

- `scroll-3x-slow.mp4`
- `scroll-frames.jpg`：3.2–6.6 秒连续录制帧；末尾黑色空格是联系表填充，不是录像黑屏。
- `scroll-small-surface.jpg`
- `scroll-dark-background.jpg`
- `scroll-wallpaper-return.jpg`
- `scroll-keyframes.json`

这些现象与替身背景、源窗口恢复／重绘时机有关的解释仍需源码和线程证据验证，本轮没有把推断写成根因。

### 问题 2：同页拖放后，交互／命令不再返回

在跨页拖放成功之后，将 D 拖向 C 以尝试堆叠。随后：

1. `get_snapshot` 的 CDP Runtime.evaluate 等待 15 秒超时。
2. 清理阶段的关闭概览请求再等待 15 秒超时。
3. 录像结束后发送原生 Escape，随后 CDP HTTP `/json/list` 在 3 秒上限内也没有返回。
4. 原生进程仍存在，Windows 的 `Responding` 查询为 true；fixture 窗口的实时预览计数继续增加。

因此，本轮确认的是一次**拖放后交互／命令响应异常**。不能将其表述为进程崩溃、整个桌面冻结、DWM 停止工作，或已定位的 Rust 死锁；也尚未排除 CDP、WebView2 与合成输入的共同影响。没有重复运行确认发生概率。

保存了 371,853 字节的线程转储，供下一轮定位。录像中布局没有出现预期的堆叠结果，不能仅凭鼠标释放就宣称拖放完成。
